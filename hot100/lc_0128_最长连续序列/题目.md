# LeetCode 128. 最长连续序列

- 难度：中等
- 链接：https://leetcode.cn/problems/longest-consecutive-sequence/
- 一句话：给未排序整数数组 nums，找出数字连续的最长序列长度（不要求序列元素在原数组中相邻），要求时间 O(n)。

## 输入格式（OJ 视角）

每组用例占两行：

1. 第一行 `n`：数组长度（`0 <= n <= 10^5`，允许 `n=0` 表示空数组）
2. 第二行：`n` 个整数，空格分隔（`-10^9 <= nums[i] <= 10^9`）

多组用例依次排列，**读到文件结束（EOF）为止**。

```
6
100 4 200 1 3 2
```

## 输出格式

每组用例输出一行，一个整数：该组 nums 的最长连续序列长度。

```
4
```

## 样例

in.txt 第 1~2 行 / out.txt 第 1 行：

```
输入：n=6, nums=[100,4,200,1,3,2]
输出：4
解释：最长连续序列是 [1,2,3,4]，长度 4
```

另外两个官方样例：

- `nums=[0,3,7,2,5,8,4,6,0,1]` → `9`（连续段 0~8）
- `nums=[1,0,1,2]` → `3`（去重后 0,1,2）

## 思路

最直接的想法是排序后扫一遍，但排序是 O(n log n)，不满足题目要求的 O(n)。O(n) 的关键是把"判断下一个数在不在"变成 O(1) 查找：

1. 先把所有数丢进**哈希集合 set**（顺便去重），`x in s` 平均 O(1)。
2. 遍历集合中的每个数 `x`：只有当 `x - 1` **不在**集合里时，`x` 才是一段连续序列的最小端点（起点）。
3. 对起点，从 `x` 开始不断 `+1` 往后数，数到集合里没有 `y+1` 为止，这段长度就是候选答案。
4. `x-1` 存在的数是"序列中间点"，直接跳过——它所在的那段已经被它的起点数过了。

为什么这是 O(n)：暴力做法对每个数都往后数，一条长序列会被反复数很多次，最坏 O(n²)；"只从起点数"这一刀让每个元素在 while 里最多被碰一次，总步数摊还是 O(n)。

## 复杂度

- 时间 O(n)：建集合 O(n)；外层遍历 O(1) 判断每个数；while 累加的总步数 ≤ n（每个数至多被延伸一次）。
- 空间 O(n)：集合最坏存下全部 n 个不同的数。

## 涉及知识点

- **哈希集合 set**：自动去重；`x in s` 平均 O(1)，对比 `x in list` 是 O(n) 的逐个比对——这是本题能 O(n) 的根本原因。
- **"只从起点数"**：用 `x - 1 not in s` 筛出每段连续序列的最小端点，避免重复扫描同一段。
- **摊还分析**：单个起点的 while 可能很长，但所有起点的 while 加起来，每个元素最多被访问一次。
- **去重**：`set(nums)` 同时解决了重复元素（如 `[1,0,1,2]`）的计数问题。

## 其他解法（学习对比，不提交）

**排序法**：先 `sort` 再一次扫描统计连续段，代码更直观，但时间 O(n log n)，不满足题目"O(n)"的硬要求：

```python
class SolutionSort:
    def longestConsecutive(self, nums: List[int]) -> int:
        if not nums:
            return 0
        nums.sort()                     # O(n log n)
        best = cur = 1
        for i in range(1, len(nums)):
            if nums[i] == nums[i - 1]:  # 重复元素跳过，不打断当前段
                continue
            if nums[i] == nums[i - 1] + 1:
                cur += 1                # 连续，段长 +1
            else:
                cur = 1                 # 断开，重新开始一段
            best = max(best, cur)
        return best
```

排序法在面试追问"能不能 O(n)"时要能升级到本题的集合法。**提交请用 `Solution` 那份。**

## 易错点

- **用 list 做查找容器**：`y+1 in [...]` 是 O(n)，整体退化成 O(n²)；必须用 `set`。
- **每个数都往后数**：不判断 `x-1` 是否存在，一条长序列会被中间每个元素各数一遍，最坏 O(n²)；只有起点才延伸。
- **重复元素**：`[1,0,1,2]` 若不去重，while 会把重复值算进长度；`set(nums)` 自动去重。
- **空数组**：`n=0` 必须返回 0，`best` 初值设 0 天然覆盖，别写成 1 或直接索引。
- **遍历 nums 而非 set**：重复元素会重复进入循环，虽不影响正确性但多做无用功；遍历集合只看不同值。
