# LeetCode 1. 两数之和

- 难度：简单
- 链接：https://leetcode.cn/problems/two-sum/
- 一句话：在数组里找出和为 `target` 的两个整数，返回它们的下标。

## 输入格式（OJ 视角）

每组用例占三行：

1. 第一行 `n`：数组长度
2. 第二行：`n` 个整数，空格分隔
3. 第三行 `target`

多组用例依次排列，**读到文件结束（EOF）为止**。题目保证每组都有且仅有一组答案，同一下标不能用两次。

```
4
2 7 11 15
9
```

## 输出格式

每组输出一行，两个下标用空格分隔，**较小的下标在前**。

```
0 1
```

## 样例

in.txt 第 1~3 行 / out.txt 第 1 行：

```
输入：n=4, nums=[2,7,11,15], target=9
输出：0 1        （nums[0] + nums[1] = 2 + 7 = 9）
```

## 思路

一次遍历 + 哈希表：边扫边记。扫到 `x` 时先查 `target - x` 是否已经见过（见过就直接返回两个下标），没见过才把 `x` 和它的下标登记进哈希表。

暴力双重循环要 O(n²)；把"找补数"从遍历数组换成查哈希表，"边查边存"一趟扫完就是 O(n)。

## 复杂度

- 时间 O(n)：每个元素最多进表一次、查表一次，均为 O(1)。
- 空间 O(n)：最坏情况（答案在末尾）哈希表存下前 n-1 个元素。

## 涉及知识点

- **哈希表（dict）**：`key in d` 与 `d[key]` 平均都是 O(1)，这是把 O(n²) 降到 O(n) 的关键。
- **`enumerate(iterable, start=0)`**：遍历时同时给出下标与元素，返回惰性迭代器。
- **循环变量解包**：`for i, x in enumerate(nums)`。
- **复杂度陷阱**：`in` 对 list 是 O(n)，对 dict/set 才是 O(1) —— 用错容器等于没优化。
- **空间换时间**：多花 O(n) 存哈希表，换来一个数量级的时间下降，这是最常见的取舍。

## 易错点

- **先存后查**：先 `seen[x] = i` 再判断，会让同一个元素匹配到自己。`nums=[3,3], target=6` 会错出 `0 0`。
- **返回顺序反了**：写成 `[i, seen[need]]`，本题要求小下标在前。
- **只记值不记下标**：哈希表要存 `值 -> 下标`，存成 set 就拿不到答案。
- **用 list 当查找容器**：`need in list` 是 O(n)，整体退化回 O(n²)。
